# Maintaining this profile

Everything visual in `README.md` is either a hand-written SVG in `assets/`
(generated by `tools/`) or a URL to a badge/stats service. There is no build
step and no dependency to install — Python 3 is only needed if you want to
regenerate the art.

---

## Publishing it

The README shows up on your GitHub profile only if it lives in a repository
named exactly like your username.

```bash
gh repo create barisyesil --public --description "Profile README"
```

Then, from inside this folder:

```bash
git init && git add . && git commit -m "Add profile README"
```

```bash
git branch -M main && git remote add origin https://github.com/barisyesil/barisyesil.git && git push -u origin main
```

Open <https://github.com/barisyesil> — the README renders on your profile.

> If the repo already exists, skip `gh repo create` and just add the remote.

## Adding a project

1. Put a **16:9 image or GIF** in `assets/projects/`. `800x450` is the sweet
   spot — big enough to stay sharp, small enough to load fast. Keep GIFs under
   about 5 MB or GitHub will be slow to show them.
2. Open `README.md` and find the `FEATURED PROJECTS` table.
3. Copy the ready-made `<td>` block from the **ADD A PROJECT** comment directly
   below that table, paste it into the table, and fill in the four fields.

The table is two cells per row. After every second `<td>`, close the row with
`</tr>` and open a new `<tr>`.

Until a project has its own picture, leave the `src` pointing at
`assets/projects/_placeholder.svg`. It renders as a deliberate "NO SIGNAL" CRT
card, which looks intentional — a missing file shows a broken-image icon, which
does not.

## Changing the colours

All nine colours live in one place: the `P` dictionary at the top of
`tools/kit.py`.

| Key | Default | Used for |
| --- | --- | --- |
| `void` | `#0d0221` | page-dark background of every asset |
| `panel` | `#1a0b2e` | inner panels, plates, badge backgrounds |
| `grid` | `#3d2a63` | perspective grid, borders |
| `magenta` | `#ff2e97` | primary accent, frames, headline shadow |
| `cyan` | `#00e5ff` | secondary accent, corner pixels, cursor |
| `purple` | `#a45cff` | tertiary accent, icon bodies |
| `sun` | `#ffcc00` | highlight, typewriter text |
| `bone` | `#e8e3ff` | body text |
| `muted` | `#7a6ba3` | secondary text |

Edit them, then regenerate:

```bash
python tools/gen_assets.py
```

The stat-card and badge URLs in `README.md` carry the same hexes as query
parameters, so search `README.md` for the old values and replace them too —
otherwise the cards will drift out of the palette.

## Regenerating the art

```bash
python tools/gen_assets.py
```

| File | What it draws |
| --- | --- |
| `tools/pixelfont.py` | the 5x7 bitmap font, including `Ş`, `İ`, `Ğ`, `Ç`, `Ö`, `Ü` |
| `tools/kit.py` | palette, borders, scanlines, sprite helper |
| `tools/gen_hero.py` | the animated hero banner |
| `tools/gen_parts.py` | section plates, divider, tags, placeholder, footer |
| `tools/gen_desk.py` | the About-section desk vignette |

To change the phrases the hero types, edit `PHRASES` in `tools/gen_hero.py`
and regenerate. To change the name, edit `name` in `gen_hero.build()` — any
character in the font works, and unknown characters fall back to a space.

## Previewing before you push

`_preview.html` renders `README.md` in a GitHub-dark shell so you can check
your changes locally:

```bash
python -m http.server 4173
```

Then open <http://localhost:4173/_preview.html>. There is a light/dark toggle
in the top bar and an asset gallery at `?view=assets`.

It is a local convenience only — delete `_preview.html` if you would rather it
not sit in the repo.

## The stat cards (read this one)

The two cards under **GITHUB STATS** come from
[`github-readme-stats`](https://github.com/anuraghazra/github-readme-stats).
Its free public instance is shared by millions of READMEs, so it is regularly
rate-limited and is sometimes **paused entirely** — as it was when this profile
was built. When that happens both cards show as broken images.

The fix is to run your own copy. It is free, takes about three minutes, and it
never rate-limits you:

1. Fork <https://github.com/anuraghazra/github-readme-stats>.
2. Create a GitHub personal access token with **no scopes at all**
   (Settings > Developer settings > Tokens (classic) > Generate).
3. Import the fork at <https://vercel.com/new> and add an environment variable
   `PAT_1` set to that token. Deploy.
4. Vercel gives you a URL like `https://your-stats.vercel.app`. In `README.md`,
   replace both occurrences of `github-readme-stats.vercel.app` with it.

The streak card comes from a different service
(`streak-stats.demolab.com`) which was healthy at build time and needs nothing.

## The contribution snake

`.github/workflows/snake.yml` draws a snake eating your contribution graph and
commits it to the `output` branch every night at 03:00 UTC (and on every push
to `main`). The README embeds it straight from that branch, so it is already
on and needs no maintenance.

To refresh it by hand: **Actions** tab > *Generate contribution snake* >
**Run workflow**. If a run ever fails with a permissions error, set
**Settings > Actions > General > Workflow permissions** to
**Read and write permissions**.

## Things worth knowing

- **GitHub strips `<style>`, `<script>`, `class` and `style` from READMEs.**
  That is why every animation lives *inside* an SVG file — an SVG loaded through
  `<img>` keeps its own CSS and SMIL and animates normally. If you add styling,
  put it in the SVG, never in the README.
- **Images go through GitHub's camo cache.** After you change an asset, the old
  version can linger for a few minutes. A hard refresh usually clears it.
- **Every asset paints its own dark background**, so the profile looks the same
  whether a visitor uses GitHub's light or dark theme. If you add art, keep that
  rule or it will disappear against a white page.
- **The divider is the exception** — it is transparent on purpose, so it reads
  as coloured pixels on both themes.
- **Alt text is not decoration.** Screen readers and broken images both fall
  back to it, so keep it meaningful when you copy a block.
